# SIH25170 UI Design System

## Design Direction

Use the approved simple, light interface direction.

The design should resemble a trustworthy public/scientific application.

## Color Direction

Base: - white - very light neutral backgrounds - dark readable text -
soft borders

Accent: - restrained green for nature/positive information - restrained
blue for water/information - restrained purple only where useful for AI
or technical features

Do not use neon colors.

Do not make gradients a major part of the design.

## Typography

Use a highly readable sans-serif font.

Prioritize: - large readable headings - comfortable body text - clear
labels - strong contrast

Avoid tiny technical text in the default interface.

## Cards

Use cards only when they improve grouping.

Good: - Vegetation result - Built-up result - Water result

Bad: - Putting every button and sentence into separate cards

## Buttons

Use clear words.

Good: - Upload image - Select area - Compare images - Ask a question -
See details - View change map

Avoid icon-only buttons unless the meaning is universally obvious.

## Icons

Use familiar icons: - map - upload - calendar - leaf - building -
water - history - help - language

Icons should support labels, not replace them.

## Map/Image

The main image should be visually dominant.

Controls should be minimal: - zoom - reset - fullscreen - map/layer
control only when necessary

## Status Colors

Use semantic colors consistently: - green = completed/positive - blue =
information - amber = processing/warning - red = error

## Animation

Keep animation subtle.

Allowed: - loading progress - panel transitions - image loading - small
feedback animations

Avoid: - floating decorative objects - animated backgrounds - excessive
motion - parallax

## Accessibility

Support: - keyboard navigation - visible focus - readable contrast -
large touch targets - semantic labels - reduced motion

## Responsive Design

Mobile is important.

On mobile: - one main column - image first - findings below - AI chat
below findings - technical details in expandable sections

Never require horizontal scrolling for the primary workflow.

## Language Selector

Provide a visible language option.

Initial UI can support English, with architecture ready for Indian
languages such as Hindi and Marathi.

Translated content must use simple, natural wording.
